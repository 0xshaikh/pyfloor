pyfloor

Audit the Python version floor of your project before it silently breaks in CI.

Get started Usage GitHub
$ pyfloor check samples/broken

What pyfloor checks

One command, every place a Python version is declared, cross-checked for consistency, CI coverage, and source-level feature drift.

collect

Multi-manifest scan

Reads the floor from pyproject.toml, setup.py/setup.cfg, .python-version, .tool-versions, tox.ini, noxfile, Pipfile, Dockerfiles and GitHub Actions workflows.

FLOOR_NOT_TESTED

CI floor coverage

Verifies the declared floor actually appears in the CI matrix, so your oldest supported version is never silently dropped.

CODE_NEEDS_NEWER

Code feature floor

Flags syntax and stdlib API usage — match, tomllib, walrus, PEP 604 unions — that requires a newer Python than the floor.

DECL_MISMATCH

Declaration consistency

Warns when different manifests declare conflicting floors, so one stale file can't quietly override the others.

--json

JSON output

Machine-readable output for pre-commit hooks, dashboards, or your own CI reporting.

exit code

CI gate

Non-zero exit on errors by default. --no-fail to report without blocking, --strict to treat warnings as failures.

Install in seconds

Zero dependencies, pure standard library, Python 3.10+. Runs anywhere Python runs.

$ pipx run pyfloor check .
$ pip install pyfloor

Usage and output

Plain ASCII output — safe on any terminal, easy to grep, no box-drawing glyphs.

Subcommands & flags

check [path]

Full audit

Scans declarations, CI coverage and code features. --json, --no-fail, --strict.

declarations [path]

List sites

Show every version declaration source with its floor, raw spec and CI versions.

features [path]

Code only

Run just the code-feature floor check, without the manifest scan.

version

Print version

Print the installed pyfloor version.
